# UX 审计 — 工作流感知缺失问题

审计日期: 2026-05-27
审计范围: 前端全流程 — Dashboard → Inbox → PipelineTaskDetail 实时反馈链路

---

## P0 — 主页面零实时更新

**症状**: Dashboard/Inbox 任务状态永远停滞在页面加载时的快照，用户必须手动刷新浏览器。

**影响文件**:
- `src/views/Dashboard.vue:194` — onMounted 一次性 fetch，无后续更新
- `src/views/Inbox.vue:92` — 同上

**根因**: 两个视图各自独立 fetch，未接入已有的 `usePipelineStore.startEventStream()`。

---

## P0 — 任务提交后的黑洞期

**症状**: 用户提交任务 → 跳转到详情页 → SSE 建立前事件丢失，排队期间无进度提示。

**影响文件**:
- `src/views/Dashboard.vue` submitTask → clarify gate → router.push
- `src/views/PipelineTaskDetail.vue:1627` setupSSE（在 onMounted 中建立）

**根因**: SSE 订阅在目标页 onMounted 中建立，非提交页预建立。ExecutionLivePanel 依赖 isRunningNow，排队期间为 false。

---

## P0 — SSE 连接状态不可见

**症状**: SSE 断连后用户无感知，不知道实时更新已失效。

**影响文件**:
- `src/services/pipelineApi.ts` subscribePipelineEvents（有 onStatusChange 但无人用）
- `src/views/PipelineTaskDetail.vue:1628`（调用时不传 onStatusChange）

---

## P1 — 相对时间标签不刷新

**症状**: "刚刚" 永远显示 "刚刚"，10 分钟前的更新看起来像刚刚发生。

**影响文件**: `src/components/inbox/TaskTable.vue` relativeTime/freshnessClass

---

## P1 — queueDepth 死代码

**症状**: Inbox 获取了队列深度但从未渲染。

**影响文件**: `src/views/Inbox.vue:58` queueDepth ref，模板无引用

---

## P2 — 无全局 SSE 连接

**症状**: 页面切换时 SSE 断连重建，浪费资源且有事件丢失窗口。

**影响文件**: `src/App.vue`（无 SSE 管理），各视图独立 subscribe

---

## P2 — 无系统健康指示器

**症状**: 后端离线用户不知道，backendOffline 只在首次失败时设 true，不重试。

**影响文件**: `src/views/Dashboard.vue`, `src/views/Inbox.vue`
