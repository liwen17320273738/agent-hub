## 第三轮修复（Pipeline 任务卡死 — 用户反馈"没有一个成功的/都在执行/非常慢/设计图没有/架构图开玩笑"）

### 根因分析
1. **后端频繁重启**: WatchFiles `--reload` 模式检测到 pipeline_engine.py 和 token_tracker.py 变更后 3 次重启，杀死正在运行的 pipeline 任务
2. **orphaned active 状态**: 重启后 10 个阶段状态保持 `active` 但无实际进程执行
3. **调度器设计缺陷**: `TaskScheduler._run()` 明确不恢复运行中任务（"Running tasks are NOT persisted"）
4. **误用 advance API**: 第一轮尝试用 advance 跳过卡住阶段，导致所有阶段标记 done 但无 output → 架构图显示空白
5. **human_gate 导致暂停**: DAG 完成后因 human_gate 标记任务为 paused 等待审批

### 已修复
- 删除空壳任务 3827a2f1，新建任务重新执行
- 批量 reset paused 任务状态并重新提交 dag-run
- 数据库 10 个 stuck active 阶段已清除
- 当前 8 个任务在调度器中运行（4 running + 4 queued）

### 待处理
- **生产模式重启**: 当前仍用 `--reload`，需要改无热重载模式
- **human_gate 默认值**: 需确认模板配置是否合理（简单任务不应需要审批）
