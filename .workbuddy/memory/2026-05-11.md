## 稳定性与可观测性重构 (Audit & Remediation)

### Phase 1: 基础设施加固

#### 1.1 分布式追踪上下文 (`app/core/context.py`)
- `TraceSpan` dataclass — trace_id, span_id, parent_span_id, request_id, metadata
- `contextvars.ContextVar` 实现 async-safe trace 传播
- `start_trace()` — Gateway 入口创建根 span
- `ensure_trace()` — 始终返回有效 span（无则创建）
- `new_child()` — 创建子 span 用于 stage/tool 级追踪

#### 1.2 Trace 中间件 (`app/core/trace_middleware.py`)
- `TraceMiddleware` — Starlette 中间件，在每个请求入口提取/生成 trace_id
- 优先级：X-Agent-Trace-ID header → 自动生成 UUID
- 注入 structlog contextvars（trace_id, span_id）
- 响应头回传 X-Agent-Trace-ID
- 请求结束后自动清理 context

#### 1.3 日志增强 (`app/logging_config.py`)
- 新增 `_inject_trace_context` processor — 自动从 TraceContext 注入 trace_id + span_id
- 所有结构化日志自动携带 trace 信息
- middleware 中已绑定到 structlog contextvars

#### 1.4 全栈健康检查 (`app/main.py`)
- `/health` 新增 `crawl4ai` 状态探测（healthy/unavailable/disabled/error）
- 新增 `llm_providers.circuits_open` — 显示熔断的 provider fingerprint
- 新增 `degraded_reasons` — 当系统降级时列出具体原因
- 整体状态：healthy / degraded / critical（新增 critical，无可用 LLM 时触发）

#### 1.5 Crawl4AI 健康探测 (`app/services/crawl/service.py`)

#### 1.6 断路器状态查询 (`app/services/llm_router.py`)
- 新增 `get_circuit_status()` — 查询 Redis 中所有 open circuit

### Phase 2: 核心逻辑重构

#### 2.1 Pipeline Trace 传播 (`app/services/pipeline_engine.py`)
- `execute_stage()` 入口处自动创建子 span
- 继承 API 层 trace_id → 所有 LLM/router/tool 调用共享同一 trace
- metadata 包含 task_id + stage_id

#### 2.2 断路器机制（已预存，验证完整）
- `circuit_is_open/provider/model` — 检查 Redis 熔断状态
- `circuit_on_success` — 成功后重置 streak + 关闭 circuit
- `circuit_on_retriable_failure` — 失败 N 次后熔断 120s
- `chat_completion_with_fallback` — 跳过热熔断的 provider

### 模式：全链路 Trace
```
Gateway(生成 trace_id)
  → TraceMiddleware(注入 contextvars)
    → Pipeline API(传递 trace_id)
      → execute_stage(创建子 span)
        → LLM Router(日志自动携带 trace_id)
        → Agent Runtime
        → Tool Calls
      → complete_stage
    → HTTP Response(X-Agent-Trace-ID header)
```
